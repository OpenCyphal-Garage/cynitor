# The pythoncan extra pulls python-can, which the CAN hub needs (can_hub.py,
# and pycyphal.transport.can.media.pythoncan for its channel). pycyphal
# declares it only as an optional extra, so a plain `pycyphal` install fails
# with "No module named 'can'" — on a fresh checkout as well as in a frozen build.
# Within 1.27: Cynitor relies on some of pycyphal's internals, which a minor
# release may change (tests/test_pycyphal_internals.py lists them). Widen it
# once those tests pass on the next one.
pycyphal[transport-can-pythoncan]>=1.27.1,<1.28
# That extra takes any python-can 4. slcan adapters run CAN FD from 4.6 on;
# an older one ignores the data bitrate, and the bitrate with it.
python-can[serial]>=4.6,<5.0
# 3.12.14 fixes request smuggling (CVE-2025-53643) and the aiohttp advisories before it.
aiohttp>=3.12.14,<4.0
numpy>=1.20,<3.0
# Reads cynitor.toml (config_file.py) where the standard library cannot: tomllib came in Python 3.11.
tomli>=2.0; python_version < "3.11"
# Windows only: candleLight adapters such as the CANable (python-can "gs_usb")
# are reached through pyusb, which needs a libusb DLL that Windows does not
# ship. libusb-package bundles it; startup_setup puts it on PATH. On Linux the
# kernel's gs_usb driver exposes these adapters as SocketCAN instead. pyusb
# comes with gs_usb, and is named for gs_usb_fd, which uses it directly.
gs_usb>=0.3; sys_platform == "win32"
pyusb>=1.2; sys_platform == "win32"
libusb-package>=1.0.26; sys_platform == "win32"
